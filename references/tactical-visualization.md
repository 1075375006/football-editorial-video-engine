# Tactical Pitch Kit

The Tactical Pitch Kit is the reusable football stage for `TACT-01`, `TACT-02`, and `TACT-03`. The pitch geometry, coordinate system, marker rules, and movement interpolation are fixed. A scene may change the surface theme, crop, perspective, attacking direction, players, and tactical events.

## Coordinate contract

All new tactical data uses normalized coordinates:

```ts
type PitchPoint = {x: number; y: number}; // both 0..1
```

`x = 0` is the team's own goal line, `x = 1` is the opponent's goal line, `y = 0` is the upper touchline, and `y = 1` is the lower touchline. `attackDirection: 'right-to-left'` flips every player, zone, arrow, and movement path together. The renderer maps the same data to 16:9, 9:16, full-pitch, and detail crops.

The first engine release accepted `0..100` `x/y` values. The runtime still converts that legacy form, but new SceneSpecs should use `position: {x, y}` and `rect: {x, y, width, height}` in normalized space.

## Component API

```tsx
<TacticalPitchKit
  perspective="top"
  theme="editorial-green"
  attackDirection="left-to-right"
  players={players}
  movements={movements}
  zones={zones}
  arrows={arrows}
  annotations={annotations}
/>
```

Three perspectives share the same top-down coordinates:

| Perspective | Use |
| --- | --- |
| `top` | Formation and movement explanation; default |
| `isometric` | Opening or atmosphere beat |
| `detail` | Half-space, wing, box, or another cropped focus |

Themes are deliberately limited to `editorial-green`, `paper-tactical`, and `mono-focus`. They change the surface texture, line colour, zone opacity, and emphasis colour while keeping field geometry stable. The surface is CSS/SVG generated; a pitch PNG is never required.

## Tactical events

Story planning describes a named event instead of inventing per-frame JSX:

```ts
const movements = [{
  id: 'saka-inside',
  playerId: 'saka',
  action: 'inside-run',
  from: {x: 0.78, y: 0.18},
  to: {x: 0.66, y: 0.37},
  startFrame: 18,
  durationInFrames: 18,
  showTrail: true,
  annotation: 'INSIDE',
}];
```

The supported actions are `inside-run`, `overlap`, `cover`, `drop`, `press`, `rotate`, and `switch`. `positionForPlayer()` interpolates `from → to` with the shared editorial easing and holds at `to` after the event. Multiple events for one player run in timeline order. Movement trails and arrow strokes are generated by SVG.

## Timing contract

A normal five to eight second tactical beat follows the shared motion language:

```text
0–18f    players build the shape
18–36f   primary movement
24–42f   delayed supporting movement
36–54f   trails and arrows draw
48–66f   target zone reveals
66f+     everything holds for reading
```

The component uses `M07 tactical-build`, `M08 line-draw`, and `M05 focus-push` timing. Player positions stop at their destinations; there is no continuous floating or ad hoc spring physics.

## Scene patterns

- `TACT-01 Formation Board` uses the full pitch and builds the starting shape in positional order.
- `TACT-02 Tactical Mechanism` keeps the relevant five to eight players, then stages the named moves, trails, target space, and conclusion label.
- `TACT-03 Space Reveal` can set `focusPlayerIds` and `focusZoneId`. The full scene appears first, non-focused players and the pitch fade, then the focus zone and arrow hold in place.

The `tactical` object on a `SceneSpec` carries these fields, so the same data can be validated, rendered offline, and reused in another aspect ratio:

```json
{
  "tactical": {
    "perspective": "top",
    "theme": "editorial-green",
    "attackDirection": "left-to-right",
    "players": [],
    "movements": [],
    "zones": [],
    "arrows": []
  }
}
```

See [`examples/tactical-pitch-kit.json`](../examples/tactical-pitch-kit.json) for a complete offline mechanism fixture.
